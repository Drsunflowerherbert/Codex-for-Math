# Verification evidence and limits

The formalisation source is pinned in `formalisation-manifest.json`, including all dependency revisions and configuration hashes. `static_lean_audit.py` is an audit-authored lexical scanner: it erases nested comments and strings, scans noteworthy tokens and computes local module import closure. It does not elaborate Lean, inspect compiled theorem axioms or establish declaration-level proof reachability.

Reproduction with an independently obtained checkout at the pinned commit:

```sh
python3 static_lean_audit.py /path/to/HolomorphicAnosov static-lean-audit.json
```

The complete static result and concise summary are included. A supplemental raw-keyword review found 116 keyword-hit lines, only five active code hits (four challenge `sorry` placeholders and one cache-clearing `run_cmd`). No keyword-hit line contained a double quote. No active custom `syntax`, `macro`, `elab` or `initialize` declaration was found. Targeted searches for kernel-bypass options, native-evaluation proof shortcuts and environment mutation found only the disclosed challenge cache clearing, outside the solution closure. These supplemental observations remain source searches, not compiler guarantees.

The preceding source-only phase initially had only Lean 4.24.0 available. An explicitly authorized follow-up installed the official Lean 4.35.0-rc1 release and all nine pinned dependencies in an isolated checkout. Its actual solution-closure build and complete type/selected definition/compiled axiom checks passed. The official comparator was attempted and failed before comparison because Bubblewrap could not set up a user namespace on this host. See [the compiled verification methods and results](compiled-verification/deliverables/verification-method.md), including the separately recorded proof replay, original unsuccessful audit attempts, source/artifact hashes and provenance. `formalisation-actions.json` remains a historical read-only API observation (zero visible workflow runs), not evidence against builds elsewhere.

`ghys-fact1-counterexample-and-repair.md` gives the exact auxiliary counterexample and the intersection-graph repair. The coordinate JSON is supplementary; the proof is exact. The accompanying original PNG/SVG figure is generated by `plot_ghys_counterexample.py` using standard Python, NumPy and Matplotlib.

Citation ledgers and bounded search logs distinguish original statement checks, proof checks, independent reconstruction, unresolved audit steps, and foundational inputs accepted without recursive proof audit. HTTP challenge or empty responses were not treated as checked article contents. Metadata-only fetch logs are included; third-party source scans and transcriptions are excluded.

`pdf-render-check.json` records page counts and text-boundary checks. Every report PDF page was rendered and inspected on contact sheets; selected formula, table and illustration pages were also inspected at full size. This checks presentation, not mathematical validity.

`publication-remote-heads-before.txt` records the public repository heads before publication. The review is added on a new branch, without changing or merging existing heads. Remote commit and file contents are verified separately at publication time. The compiled follow-up updates only the existing review branch; all other branch heads and files outside this review directory are checked for preservation.

The audit-authored `verify_published_files.py` downloads only immutable public raw files and compares each SHA-256 against `SHA256SUMS`. It accepts the full publication commit as its argument. It never executes downloaded material. A publication verification record, when present, identifies the exact earlier content commit it checked; it is not a Lean build record.

Compiled evidence publication normalizes private absolute paths. Each published file has a byte hash in the root manifest; the normalization record separately retains raw file hashes and published hashes. Raw log hashes in run metadata refer to original private bytes and are labelled accordingly. Large toolchain/cache/build/proof-export artifacts are excluded; their identities and the completed export hash are recorded. Earlier source-only notes and manifests are retained with phase labels and a link to the follow-up.
